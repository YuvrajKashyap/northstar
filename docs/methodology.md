# Deterministic scenario methodology

Northstar's scenario is a reproducible product evaluation path. It is not a backtest, Monte Carlo simulation, market forecast, portfolio optimization, or financial recommendation.

## Fixture

The canonical fixture is generated by `scripts/generate_demo_seed.py` with:

- random seed: `20260501`
- as-of date: `2026-05-02`
- persona: Maya Patel, a synthetic investor

`npm run seed:check` regenerates the JSON in memory and fails if the checked-in file differs. The fixture contains invented accounts, holdings, tax lots, transactions, goals, and preferences. Institution and security names are used as recognizable test labels; they do not imply integrations or endorsements.

## Stress calculation

For a market shock `s`, each holding value `V` is transformed with an explicit asset-class sensitivity `k`:

```text
shocked value = V * (1 + s * k)
```

| Asset class | Sensitivity `k` |
| --- | ---: |
| Stock | 1.00 |
| ETF | 0.85 |
| Mutual fund | 0.70 |
| Cash | 0.00 |

The implementation then computes the portfolio loss, withdrawal amount, available cash, liquidity gap, and liquidity coverage. The displayed goal-delay estimate divides the gap by a simple 48-month target pace. That is an explanatory heuristic, not a probability-weighted result.

## Path comparison

The three paths are deterministic transformations of the baseline result:

| Path | Modeled stress loss | Liquidity coverage | Top-three concentration |
| --- | ---: | ---: | ---: |
| Do nothing | Baseline | Baseline | Baseline |
| Balanced protection | 70% of baseline loss | Baseline + 40 points, capped at 100% | 75% of baseline |
| Maximum safety | 45% of baseline loss | 100% | 55% of baseline |

The selection rule chooses **Balanced protection** as a transparent middle heuristic: it reduces modeled loss and concentration while retaining more growth exposure than the maximum-safety path. In the canonical run it still leaves a liquidity gap, which is why the receipt remains approval-gated. The model does not calculate expected returns, transaction costs, slippage, or real portfolio allocations.

## Tax context

Northstar sums positive differences between synthetic holding value and cost basis. It labels the magnitude for discussion but does not estimate tax liability. Real tax work would require at least holding period, filing status, income, realized gains and losses, account registration, jurisdiction, and current law.

## Trust receipt

The receipt records:

- why the scenario was considered;
- which path the deterministic rule selected;
- the modeled liquidity gap;
- confidence boundaries;
- the explicit `approval_required` state;
- the fact that no trade, transfer, or tax action was executed.

Backend tests verify that the calculation is deterministic, responds monotonically to a more severe shock, and keeps human approval in the receipt.
