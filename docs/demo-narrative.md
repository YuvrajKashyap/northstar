# Hackathon demo narrative

This readable outline preserves the story from the original `Northstar_Product_Demo_Deck.pptx`, added by Kushagra Bharti during the hackathon. The binary accumulated invalid PowerPoint shadow values and mojibake, so it was removed from the current tree after the narrative and product visuals were preserved. The original remains available in Git history.

## 1. Memory-first financial agent

Northstar turns personal financial context into durable memory, then gives the user one visible agent—North—to explain what matters before they act.

## 2. The problem

Beginners do not need more market noise. They need a system that understands timing, cash needs, risk behavior, taxes, and approval boundaries. The wedge is to start with memory and reason against the person rather than only the portfolio.

## 3. Product loop

Onboarding compiles `memory.md` and `context_packet.json`. North loads that context, calls tools, streams a trace, and returns an approval-gated decision.

## 4. Memory graph

The user sits at the center of connected goals, accounts, cash flow, values, tax context, and risk comfort. The graph makes agent grounding inspectable rather than leaving it inside a blank chat.

## 5. Goals as constraints

Goals carry a target, timing, confidence, and supporting memory signals. North interprets the portfolio through the active goal instead of optimizing a generic benchmark.

## 6. One visible agent, specialist tools

The user talks to North. Behind it, memory, portfolio, research, scenario, and receipt tools produce one transcript and a visible event trace.

## 7. Compare futures before reacting

The hero scenario asks what happens if markets fall 20% and the user needs cash within a year. Output separates assumptions and heuristic paths from the final approval state. North can explain and prepare; it does not trade or move money.

## 8. Trust promise

Remember the person, use the right tools, and show the work. Financial execution remains explicit and user-approved.
